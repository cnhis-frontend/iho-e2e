# 更新已接入的项目

使用 `update` 同步工具包管理的文件，无需手动复制，也不必重新初始化项目。默认预览；`--apply` 才写入。工具包当前通过源码 checkout 分发，尚未发布 npm 包。

## 直接复制给 AI

在能读写项目文件、运行终端命令的 AI 中，完整复制以下文本即可，无需提供此前聊天记录。默认目标是工作区中唯一已接入 IHO 测试工具包的业务项目；也可以在文本前补充“目标项目：<绝对路径>”。这段请求包含升级未定制的标准本地规则；若只更新工具，将第 4 项改为“保持全部规则固定版本不变”。


## 从工具包 checkout 更新

先取得希望同步的工具包版本。已有 checkout 可切换到指定提交或 tag；需要更新远端分支时，在确认本地改动已妥善保留后使用 Git 更新。命令使用该 checkout 的实际文件，未提交内容会在报告中标为 `dirty`，并用内容摘要定位；不会自动拉取、重置或推送任何仓库。

```sh
node <工具包目录>/bin/iho-test.mjs update --project <项目绝对路径>
node <工具包目录>/bin/iho-test.mjs update --project <项目绝对路径> --apply
```

这会同步两个 skill 和它们共享的 CLI、公共规则副本及文档快照，更新 profile 的 `toolkitVersion`，生成 `iho-test.lock.json` 记录来源版本、可取得的 Git 提交及内容摘要。源码目录路径不写入锁文件。旧项目无需提前拥有锁文件，旧安装清单用于识别受管理文件。

交给 AI 执行时，复制上方“直接复制给 AI”的完整文本，其中已包含项目识别、官方源码和版本选择方式。

## 从项目内入口更新

已有支持 `update` 的快照，可以从项目目录执行：

```sh
node .agents/skills/iho-test-bootstrap/scripts/run.mjs update --project . --source <新工具包checkout路径> --apply
```

`--source` 指向上游源码 checkout，不是其他项目的内置 runtime。更新器会预读源文件，再替换项目内快照，因此项目内入口可更新自身。尚不支持 `update` 的旧快照，首次从新版 checkout 的 CLI 执行即可。更新后运行测试仍不依赖这个 checkout。

## 公共规则单独选择升级

内置工具副本更新后，项目 profile 固定的规则仍可能是旧版本。默认保持固定规则，以免工具升级悄悄改变测试规范。需要同时升级工具包管理的本地规则时：

```sh
node <工具包目录>/bin/iho-test.mjs update --project <项目绝对路径> --update-rules
node <工具包目录>/bin/iho-test.mjs update --project <项目绝对路径> --update-rules --apply
```

仅升级 `tests/knowledge` 标准本地快照。更新前校验旧清单/锁文件、profile 固定摘要和规则内容，确认项目未定制；再校验新 catalog 与正文并更新 profile 摘要。可以先更新工具、之后再升级规则，锁文件会保留旧规则的管理基准。旧 catalog 不再引用的文件保留，需另行确认用途后清理。

自定义规则目录、Git 和 OpenViking 的来源及连接配置保持原样，更新命令不连接知识服务。显式 `--update-rules` 遇到这些来源会停止，并说明应通过对应来源的审查流程升级固定版本。

## 冲突和项目适配

受管理 skill 文件被项目修改、规则摘要漂移、未知文件占用目标路径或路径指向链接时，报告具体冲突并在写入前停止。不要通过删除清单、重算摘要或覆盖文件绕过检查。由 AI 对照新旧内容合并有意定制，或将项目规则移到项目文档/支持层；无法确定意图时再询问用户。预览后源文件或项目配置发生变化时，重新预览。

配置、依赖和锁文件、宿主实现、业务测试及项目测试说明属于使用方，`update` 不用模板覆盖它们，也不重新安装依赖。同步后的报告包含剩余适配步骤：例如补齐 `scripts.host`、调整自定义类型检查 include，以及适配所选版本要求。AI 应按新版 `project-adaptation.md` 对这些项目文件做必要的增量修改，并根据实际能力验收；这部分不能用通用文件替换完成。

`applied: true` 只表示同步完成，`validation: not-run` 明确表示未验收。接着运行项目内 `doctor --host`；已有业务套件时运行 `doctor --run`。按公共规则“会话报告与项目说明”，规则版本、实际验证范围及失败项仅在用户会话中报告。两个 skill 目录、`iho-test.lock.json` 和必要的 profile/规则/适配改动应一起纳入使用方版本控制；提交遵循用户授权。

应用前会检查所有已知冲突并再次校验计划；这不是跨文件系统事务。写入期间的磁盘故障需通过项目 Git 差异恢复后重试。更新器不自动提交或推送。
